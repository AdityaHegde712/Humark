# Humark Confirmed Behavioral Defect Log

This document records confirmed behavioral defects discovered during working-run verification or user testing.

## B-001 — Physical Number Key Input Failure on Challenge Card
- **Observed Behavior**: User reported key '1' does not register selection for Option A while 'A' worked.
- **Design Vulnerability**: Coupling keyboard shortcuts solely to `KeyboardEvent.key` rather than checking hardware-agnostic `KeyboardEvent.code` (`Digit1`, `Numpad1`).
- **Structural Resolution**: Check both character value (`e.key`) and physical key code (`e.code`) for top-row numbers, numpad numbers, and character letters (`Digit1`/`Digit2`, `Numpad1`/`Numpad2`, `KeyA`/`KeyB`).
- **Design Heuristic**: For gaming and speed-accuracy keyboard navigation, bind to both `e.key` (semantic glyph) and `e.code` (physical key location) to ensure universal keyboard layout compatibility.

## B-002 — Guest Session Reset Cookie Re-Attachment & Blank View Desynchronization
- **Observed Behavior**: In Fast Mode, clicking "Reset" cleared `localStorage`, but the browser re-sent the existing `humark_session_id` cookie on `POST /api/sessions`. The backend returned the completed session instead of minting a new one. `getNextChallenge()` then returned `round_completed: true` with `id: null`. In `GamePage.tsx`, `scorecard` was null while `challenge.round_completed` was true, leaving the viewport completely blank and desynchronizing view toggling.
- **Design Vulnerability**: Relying on client-side `localStorage` clearing alone while an ambient HTTP cookie persisted session identity, coupled with an idempotent `POST /api/sessions` endpoint that retained existing sessions, and a frontend rendering branch that lacked fallback UI when a round completed without a pre-loaded scorecard.
- **Structural Resolution**: Implemented `create_new_session(db)` and `POST /api/sessions/reset` to unconditionally mint a fresh session with new UUID and overwrite response cookies/headers (`humark_session_id`, `X-Session-ID`). Updated frontend `resetSession()` to expire `document.cookie` (`max-age=0`), clear `localStorage`, call `/api/sessions/reset`, and store the new ID. Added fallback UI in `GamePage.tsx` with a clean "Round Completed!" prompt and scorecard toggle so the viewport never renders empty.
- **Design Heuristic**: For state reset flows involving hybrid persistence (localStorage + HTTP cookies), expose an explicit server-side reset primitive that unconditionally supersedes ambient credentials, and guarantee exhaustive fallback rendering coverage for compound component state branches.

## B-003 — SVG Entity Parsing, Wilson NaN Interval, Dataset Bias, and Scorecard Navigation
- **Observed Behavior**: (1) Thumbnail SVGs 14b and 34b failed XML parsers due to unescaped ampersands (`&`). (2) The scorecard rendered raw unrendered LaTeX markup (`($\mu=52.8\%$, $\sigma=9.4\%$)`) and displayed `NaN%` confidence intervals due to property naming divergence (`lower`/`upper` vs `ci_lower`/`ci_upper`). (3) The benchmark dataset exhibited strong position bias with 29 A winners and 7 B winners. (4) Completing a round caused navigation deadlock when clicking "Challenge" on the scorecard toggle.
- **Design Vulnerability**: (1) SVG template string interpolation without XML entity escaping. (2) Loose TypeScript type contract divergence between backend statistical models and frontend interface consumers. (3) Non-stratified seed generation leading to asymmetric ground-truth distributions. (4) View toggle handlers in `GamePage.tsx` did not advance rounds when viewing completed round states.
- **Structural Resolution**: (1) Escaped `&` to `&amp;` across all SVG assets, verifying zero XML parse errors across all 72 files. (2) Replaced raw LaTeX with Unicode (`(μ = 52.8%, σ = 9.4%)`), expanded `WilsonInterval` interface, and added resilient fallback properties (`lower ?? ci_lower`). (3) Inverted 11 challenges in `seed_challenges.json` to achieve exact 50/50 balance (18 A / 18 B) and refreshed precomputed baseline predictions. (4) Updated `Header.tsx` to hide the "Challenge" toggle when 30 items are completed, and updated `GamePage.tsx` to trigger round progression seamlessly when toggling to Challenge after round completion.
- **Design Heuristic**: Enforce XML validation gates on generated visual assets, maintain strict bidirectional schema compatibility for statistical intervals, enforce ground-truth label balance across benchmark evaluation suites, and ensure state-dependent view toggles trigger valid domain transitions.

## B-004 — Cumulative Accuracy Percentage Double-Multiplication in Verification Badge
- **Observed Behavior**: VerificationBadge displayed `8333.0%` instead of `83.3%` upon completing the 30-item verification track.
- **Design Vulnerability**: Backend `evaluate_verification` in `verification.py` multiplied accuracy by `100.0` (`round(total_correct / len(attempts) * 100.0, 2)`), while frontend `VerificationBadge.tsx` assumed `cumulative_accuracy` was a unit proportion in `[0.0, 1.0]` and multiplied by `100` again (`(auditSummary.cumulative_accuracy * 100).toFixed(1)`), resulting in double-scaling.
- **Structural Resolution**: (1) Standardized `cumulative_accuracy` in `verification.py` to unit proportion rounded to 4 decimal places (`round(total_correct / len(attempts), 4)`). (2) Updated `VerificationBadge.tsx` with defensive normalization (`const normalized = rawAccuracy > 1.0 ? rawAccuracy : rawAccuracy * 100; const cumulativePct = normalized.toFixed(1);`). (3) Updated test assertions in `test_verification.py` and `test_e2e_gameplay.py`.
- **Design Heuristic**: Standardize all probability, ratio, and statistical accuracy metrics in backend APIs as unit proportions in `[0.0, 1.0]`; enforce defensive client-side percentage formatters that inspect magnitude bounds prior to scaling.
